STAHL SHRINE ASCII SLIDESHOW - PRIMER
======================================

What this is
-------------
An animated ASCII "slideshow" embedded in the Stahl Shrine recipe page
(content/docs/psychoactive/stahl-shrine/_index.md). Clicking a recipe step
(steps are wrapped in <span class="recipe-step" data-step="N">) reveals a
small monospace grid (#stahl-slideshow) showing props (seed pile, grinder,
shot glass, stir rod, bottle, measuring stick, fan, fridge, baking dish,
ice particles, etc.) animating from the previous step's resting frame into
the new one.

Entry point: src/stahl-recipe.ts's `init()` wires up click handlers on
`.recipe-step` elements and calls `animator.playStep(STEPS[index], index+1)`.
Built/loaded via layouts/_default/shrine-page.html
(<script type="module" src="/js/stahl-recipe.js">) and styled by
static/css/shrine.css (.recipe-ss-* classes + .recipe-step highlight).

Core architecture
------------------

1. src/ascii-compositor.ts — generic engine, no recipe knowledge.
   - `Compositor`: holds a Map of `SceneObject`s (id, sprite, x/y/z,
     rotation, visible), renders them onto a fixed-size character grid each
     frame, diffing against the previous grid so only changed <span> cells
     get touched. Sorts by z for stacking. Supports a `viewOffsetX` for
     panning an unbounded world space across the fixed-width grid.
   - `Sprite` = either a `cells: SpriteCell[]` array (each cell has dx/dy
     offset, a `role` string that resolves to a glyph via
     `registerGlyphResolver`, and alpha) or a `polygon` (array of [dx,dy]
     points rasterized fresh each frame via Bresenham line-drawing, so it
     rotates cleanly to any angle without gaps). `polygonClosed: false`
     leaves one edge open (e.g. the shot glass's top).
   - Rotation happens in continuous space (`rotateOffset`, with a
     CELL_ASPECT correction since terminal cells are taller than wide)
     before snapping to grid coordinates.
   - "wall" role cells (`wallCell`) auto-pick - | / \ based on their
     `edgeAngle` + the object's current rotation (`wallGlyph`).
   - `PropGroup`: a cluster of SceneObjects (e.g. grinder body + blade, or a
     pile of individual seed glyphs) that share one origin/rotation and move
     together via `applyOrigin()`. Members can be `release()`d to animate
     independently, or `transferTo()` another group (seeds flying from the
     pile into the grinder, then later into the glass).

2. src/ascii-sprites.ts — sprite-building helpers + extra glyph roles.
   - `cell()`, `wallCell()`, `staticRole()` (fixed-char roles like "o", "~",
     "."), `ringSprite()` (rectangular outline, e.g. baking dish),
     `polygonSprite()`, `bladeSprite(maxRadius)` (pulsing hub+arms for the
     grinder blade / stir rod: o, =o=, ==o==, ... and back).
   - `seedGrindRole(t)`: maps grind progress 0..1 to glyph stages O -> o -> .
   - `ouStep()`: Ornstein-Uhlenbeck random walk used for seed jitter during
     flight/grinding (bounded random wander).
   - `arcLerp(from, to, span, arcHeight)`: parabolic-arc interpolation used
     everywhere a prop "flies" (seed pile into grinder, ground seeds into
     glass, ethanol/acid drops, glass into fridge, ice particles falling).
   - `MemberFlight`: animates a PropGroup's origin + per-member jitter along
     an arc, then `land()`s members into a target group with new offsets.
   - `GroupArcTransfer`: one-shot timed transfer of a fixed set of members
     from one group to another along an arc, triggered by elapsed time
     crossing release/land thresholds (e.g. step 2's ground-seed pour).
   - `runFrames(duration, frame, onDone, opts)`: shared frame-stepping loop—
     either real-time via requestAnimationFrame, or, if `opts.instant`,
     synchronously in fixed 16ms steps with no rendering (used for
     fast-forwarding earlier steps and for the headless trace/dump tools).

3. src/stahl-props.ts — sprites, prop geometry, and shared layout types.
   - Defines every prop's `Sprite` (seed pile, grinder, glass, liquid/powder
     particles, stir rod, bottle, stick, fan, dish, fridge, ice, glass2,
     barley scoop, residue clumps) plus their geometry/timing constants, the
     `SPRITES` registry, and `INITIAL_LAYOUT` (every prop's position/z/
     rotation before any step is selected—step 0 state). Also the shared
     `ObjectLayout`/`FullLayout` types, `PANE_WIDTH`, `GRID_WIDTH`/
     `GRID_HEIGHT`, `TAU`, and `PROP_PARK_Y`/`STEP_PAUSE_DURATION`.
   - Constants that are core `SceneAnimator` state (e.g. `GRIND_*`,
     `LIQUID_VORTEX_*`, glass dimensions, `GLASS_FLUID_FILL`) live here even
     though they conceptually "belong" to one step, since the animator's
     constructor and methods need them directly.

4. src/stahl-timeline.ts — generic Step data model, no recipe content.
   - `TransitionKeyframe`/`Sequence`/`concatSequences`: sparse per-object
     waypoints in world space and a helper to chain self-contained
     sub-sequences (each with its own duration) into one timeline with
     offsets.
   - `Loop`/`EffectLoop`/`ContinuousSpin`/`BladePulse`: continuous
     animations (spin, blade pulse, or a recurring StepEffect) that start
     once a transition ends.
   - `StepEffect`: per-frame effect interface (`tick(t, anim)`), instantiated
     fresh per `playTransition` call, for things keyframes can't express—
     particle transfers between PropGroups, one-shot state changes partway
     through.
   - `CountdownConfig`/`formatCountdown`: the "stir for 10 min" /
     "refrigerate for 20 min" timer shown `startDelay` ms after a
     transition finishes.
   - `Step`: ties the above together (`transitionDuration`,
     `transitionKeyframes`, `loops`, `effects`, `countdown`, `onSettle`).
     `onSettle` is an optional callback fired after the transition and loops
     are fully set up (used by step 6 to trigger the fireworks finale).
   - `DropAnimation`: short-lived particle (ethanol/acid drop) state used by
     `SceneAnimator.spawnDrop`/`updateDrops`.

5. src/stahl-steps/ — one file per step (step1-grind.ts .. step6-drink.ts),
   each exporting `STEPN: Step` plus that step's own constants and per-frame
   StepEffect classes. Cross-step dependencies are plain value imports
   between these files (e.g. step4-evaporate.ts imports
   `GLASS_FRIDGE_REST`/`STIR_ROD_PARK_DURATION` from step3-fridge.ts)—safe
   since there's no cycle among the step files themselves.
     1. Grind — seed pile arcs (MemberFlight) across the pane seam into the
        grinder; once landed, `startGrinding()` (in stahl-animator.ts) runs
        the blade pulse + body shake + per-seed OU jitter for a random
        8-10s, crumbling each seed O -> o -> . via `seedGrindRole`.
     2. Mix & stir — grinder/bottle/stick each run a "pour sequence"
        (Sequence: self-contained keyframes + duration), shuffled into a
        random order at module load (`STEP2_POUR_SEQUENCES`, seeded via
        src/rng.ts's `rand()`), concatenated via `concatSequences`. Per-frame
        effects (`SeedPourEffect`, `BottlePourEffect`, `StickPourEffect`)
        fire pours/fills at offsets computed from that shuffled order. Once
        all three land, the stir rod descends and starts pulsing
        (LIQUID_VORTEX swirls the "~" particles while stirring).
     3. Refrigerate — `GlassFridgeArcEffect` arcs the glass (carrying its
        powder/liquid PropGroups) into the fridge; once landed,
        `CoverDropEffect` drops the fridge's top cover; `IceParticleEffect`
        then periodically spawns ice particles from a random vent that fall,
        sometimes vanish mid-air, and rest on the floor before disappearing.
     4. Evaporate — fridge cover lifts, then the glass arcs up out of the
        fridge and tips (pivoting around its bottom-right corner) over the
        dish to pour. Liquid spills from the glass into the dish. Poured
        liquid gradually evaporates into "." residue, with steam rising; fan
        starts a beat after the glass lands and spins until the liquid is
        gone. Glass rotates upright and arcs back to its step 2 resting spot.
     5. Final prep — dish residue, tartaric acid (stick), barley grass powder
        (barley scoop), and tap water are each a self-contained Sequence,
        shuffled into a random order at module load (same pattern as step 2's
        pours) and concatenated via `concatSequences`. Once all four land in
        glass2, stirRod2 descends into glass2 and starts pulsing.
     6. Drink — stirRod2 lifts out of glass2; after a pause, glass2 rises
        off-screen (emptied via `emptyGlass2()`), then descends back into
        view in step 6's pane. After the empty cup settles, a fireworks
        finale fires via `onSettle` (see src/stahl-fireworks.ts).

6. src/stahl-animator.ts — `SceneAnimator` plus the `applyAt`/`lerp`/
   `shortestAngleLerp` helpers.
   - Constructed with a `Compositor`; builds all SPRITES as SceneObjects
     at INITIAL_LAYOUT, plus proxy objects (`seedPile`, `grinderBody`) used
     purely as keyframe-timeline anchors for `seedGroup`/`grinderGroup`.
   - Manages `FluidContainer` instances (a PropGroup + vortex state +
     optional `FluidSim`) for each container: glass, glass2, dish, bottle,
     grinder. The fluid sim (when active) drives particle positions via
     MAC-grid FLIP; otherwise, the legacy vortex system handles stirring.
   - `playStep(step, index)`: stops any in-flight animation/loop,
     fast-forwards (instantly, no render) through steps
     `currentStepIndex+1 .. index-1` via `playTransition(..., instant=true)`
     so step `index` always starts from a deterministic state regardless of
     what was previously shown, then pans the viewport
     (`panViewport`, 800ms) to `(index-1)*PANE_WIDTH`, pauses
     STEP_PAUSE_DURATION, and plays the step's transition for real.
   - `snapToInitial`: for step 1, hard-resets everything to INITIAL_LAYOUT
     and rebuilds seed/glass/liquid groups from scratch
     (`rebuildSeedState`); for steps 2+, just reads current positions as
     the t=0 anchor and builds per-object keyframe timelines.
   - `playTransition`: runs `runFrames` over the step's
     transitionDuration, each frame applying keyframe interpolation
     (`applyAt`), keeping seed/grinder/glass/liquid PropGroup origins in
     sync, ticking the step's `effects`, and advancing drop particles
     (`updateDrops`). On completion starts `loops` (spin/pulse/effect),
     step 1's grind, the countdown, and calls `onSettle` if defined.
   - `runStepInstant(index, onFrame?)`: headless version (no pan/pause/
     render/loops) used by the debug scripts below.
   - `emptyGlass2()`: removes all particles from glass2's PropGroups and
     resets its fluid container (used by step 6's GlassEmptyEffect).
   - Imports `STEPS` from stahl-scene.ts (a value-level circular import,
     safe in ESM since `STEPS` is only read inside method bodies, never at
     module-evaluation time).

7. src/stahl-scene.ts — thin assembly/re-export shim. Imports `STEP1..STEP6`
   from src/stahl-steps/*, assembles `STEPS: Step[]`, and re-exports
   `SceneAnimator` plus the handful of names src/stahl-recipe.ts and
   scripts/*.ts depend on (`GRID_HEIGHT`, `GRID_WIDTH`, `PANE_WIDTH`,
   `GRINDER_BLADE`, `GRINDER_BLADE_RADIUS`, `GRINDER_BODY`).

8. src/iso.ts — voxel grid + projection for the fluid sim. Containers are
   cylindrical or box-shaped and viewed straight-on at their widest
   cross-section: grid x = diameter (screen column), y = height above the
   table (screen row), z = depth into the screen. `Grid3D<M>`/`makeGrid3D`
   build a dense [x][y][z] array of `Voxel<M> | null`.
   `projectColumn`/`projectGrid` walk each (x,y) column front-to-back
   (z=0 = closest to camera), blending by each material's `opacity` so
   transparent voxels (e.g. ethanol) let whatever's behind them (seed
   fragments, residue) show through, while opaque ones win outright.
   `liquidRole` maps a projected cell's material to a glyph role (registered
   via `staticRole`, same pattern as `seedGrindRole`)—"~" for
   ethanol/water, "." for seed fragments/barley powder, "@" for residue,
   "*" for steam.

9. src/fluid-sim.ts — MAC-grid Stable Fluids + FLIP particle simulation.
   - `Particle`: position + velocity + kind ("ethanol" | "powder").
   - `FluidSim`: holds dims, particles, solid voxel mask, optional
     `CylinderBounds`, viscosity, and flipRatio.
   - `makeFluidSim(spec, profile)`: creates a cylindrical container by
     rasterizing a 2D profile into a 3D solid boundary. Also supports
     rectangular containers via `makeFluidSim(dims)`.
   - `fillFluidSim(sim, levelFraction)`: fills the sim with ethanol
     particles up to the given fraction of container height.
   - `seedFluidFromPositions(sim, positions, origin)`: maps 2D
     sprite-space positions into the 3D grid and fills the corresponding
     columns with ethanol particles.
   - `seedPowderAtBottom(sim, count)`: places powder particles at the
     bottom of the container.
   - `stepFluid(sim, dt, stir)`: one simulation step—particles-to-MAC-grid
     transfer (trilinear splatting), gravity + optional `StirImpulse`
     forces, viscosity diffusion, solid boundary enforcement, Gauss-Seidel
     pressure projection, FLIP/PIC velocity blend back to particles,
     advection, powder/ethanol displacement, and particle separation.
     CFL sub-stepping keeps things stable at high velocities.
   - `projectFluidSim(sim)`: projects the 3D particle state into a 2D
     front-view grid (center z-slice only) for rendering.
   - `gridToRel` / `interiorBounds`: helpers for mapping between the 3D
     grid and 2D sprite-space coordinates.

10. src/fluid-debug-3d.ts — 3D voxel visualization of a FluidSim for
    debugging. Renders particles + solid walls onto a canvas using
    azimuth/elevation camera controls, colored by particle kind.

11. src/stahl-fireworks.ts — page-wide fireworks display used as the recipe
    slideshow's finale (step 6). Rockets launch from the bottom of the
    viewport, arc up trailing sparks, then explode into scatter-burst
    particle patterns that fall under gravity and fade. Drawn on a
    full-viewport canvas overlay; the display runs for ~9.5s then unmounts.

Debug / dev tooling
--------------------
- src/rng.ts: swap-in seeded PRNG (`setSeed(n)`) for reproducible traces of
  randomized behavior (step 2 pour order, step 1 grind scatter/duration,
  step 3 ice spawns). Must be called before stahl-scene.ts is imported,
  since the pour-order shuffle runs at module load.

- scripts/dump-sprite.ts:
    npx tsx scripts/dump-sprite.ts sprite <grinder|blade> <rotation-deg>
      -> renders one sprite at a given rotation on a 24x24 grid, for
         eyeballing aspect-corrected rotation.
    npx tsx scripts/dump-sprite.ts grid <step-index 1-based>
      -> renders the full GRID_WIDTH x GRID_HEIGHT grid for a step at rest
         (after runStepInstant), mirroring Compositor.render() without DOM.

- scripts/trace-step.ts:
    npx tsx scripts/trace-step.ts [--seed=<n>] <step-index> <object-id>[,...] [every-ms]
      -> logs x/y/z/rotation for the given object id(s) every `every-ms`
         (default 16) across a step's full transition via runStepInstant,
         so StepEffects (fridge arc, cover drop, ice particles, etc.) run
         exactly as at runtime. Useful for checking timing/positions of
         multi-phase effects without a browser.

- scripts/check-iso.ts:
    npx tsx scripts/check-iso.ts
      -> assertion-based sanity checks for src/iso.ts's voxel grid +
         front-to-back occlusion projection. Exits non-zero on failure.

- scripts/check-fluid-sim.ts:
    npx tsx scripts/check-fluid-sim.ts
      -> sanity checks for src/fluid-sim.ts—settling, surface flatness,
         stir response, projection, particle conservation. Exits non-zero
         on failure, silent on success.

- scripts/debug-settle.ts:
    npx tsx scripts/debug-settle.ts
      -> diagnostic output for fluid sim settling behavior (height
         distribution, ring velocities after stirring). Used to tune
         simulation constants.

Debug UI (localhost only)
--------------------------
When `location.hostname === "localhost"`, src/stahl-recipe.ts adds pane
divider lines (`compositor.debugLinesX`), per-object id labels
(`compositor.debugLabels`), and a slider + "Reset viewport" button
(`buildDebugControls`) to manually pan the viewport via
`animator.setDebugViewOffset(x)` / `resetViewOffset()`.

Known WIP / things to watch
-----------------------------
- The recipe markdown wraps each numbered step in
  `<span class="recipe-step" data-step="N">`; `data-step` itself isn't read
  by stahl-recipe.ts (it uses DOM order / NodeList index instead)—keep
  step spans and STEPS array order in sync if either changes.
